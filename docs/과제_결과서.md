## 3. 문제 정의

### 기존 업무 방식

POSCO 철강 판매담당자는 매일 아침 거래처 응대 준비를 위해 다음을 **수동·분산** 형태로 수행:

1. MIH 시스템에서 시황 지표 10여 개를 따로 확인 (**30분/일**)
2. ERP/엑셀로 당월 가이드값 vs 누적 실적 / 전년 동월 대비 수기 합산
3. 본인 메모/엑셀로 거래처별 산업 특성·민감 이슈·과거 패턴 검색
4. 머릿속에서 종합 → 직관·경험 기반 응대 결정

### 기존 방식의 불편함 / 비효율

- **시간 낭비**: 5명 × 30분 × 240영업일 = **연 6,000시간** 비생산적 소비
- **인사이트 단절**: 시황 ↔ 자사 실적 ↔ 거래처 컨텍스트가 3개 분리 시스템
- **재현성 부재**: 직관·경험 기반 → 베테랑·주니어 응대 품질 격차
- **가이드값 추적 부재**: 월말이 되어서야 미달 거래처 발견 → 선제 대응 불가
- **노하우 사장**: 영업사원이 엑셀에 보유한 노하우가 조직 자산화되지 못함
- **도메인 지식 단절**: 산업별 베스트프랙티스 / 거래처별 과거 응대 사례를 실시간 검색 불가 → 매 LLM 호출이 정적 prompt 만 사용

### 이 문제를 해결해야 했던 이유

**5명 판매담당자 1차 인터뷰**에서 동일 키워드가 5건 모두 등장:
*"시간 부족", "통합 인사이트 부재", "가이드값 추적 어려움", "거래처 우선순위 판정 곤란", "노하우 전산화 불가"*.

→ POSCO 마케팅 DX 전환의 핵심 병목이 **현장 영업담당자의 일일 의사결정 지원** 임을 확인.
*RAG 기반 도메인 지식 검색 + LangGraph Agent로 다단계 추론* 이 정공법.

## 5. 최종 구현 결과 및 AI 활용 내용

### 5.1 최종적으로 만든 것

**두 개의 통합 대시보드 + 8개 LangGraph Agent 노드 + RAG 지식 베이스** 로 구성된 풀스택 웹 애플리케이션.

#### 5.1.1 메인 대시보드 (`/`)

거래처 응대 직전 1분 브리핑용:

1. **오늘의 추천 질문 3개** — RAG 컨텍스트(노션 PRD 도메인 방법론) 검색 후 영업담당자가 거래처에 받을 만한 질문 자동 생성
2. **답변 1분 브리핑 + 추천 대응 방안** — 클릭 즉시 BLUF 단일 단락 멘트로 응대 가능
3. **차트 1 — Top 10 변동 지표** — 본인 제품 key_features 의 W-1 변동률
4. **차트 2 — 인과 흐름** — 5 Whys 기반 5단계 인과 사슬 + 뉴스 evidence
5. **AI 진단 (WHAT/WHY/IMPACT)** — SCQA 구조로 거래처 영향 평가
6. **권장 대응 전략** — Porter 5 Forces + BATNA 기반 협상 카드 3개

#### 5.1.2 판매량 가이드 대시보드 (`/guide`)

월별 영업 성과 관리용:

7. **가이드값 달성률** — 제품 KPI + 5개 거래처별 RAG 신호등 + 전년 동월 대비
8. **기회 탐지** — 거래처별 종합 스코어 (달성속도·전년대비·시황영향) + A/B/C 등급 + Toss 미니멀 원형 ring 게이지
9. **과거 시황 학습** — Z-score 정규화 + 코사인 유사도 Top 3 유사월 + 현재 대비 delta chip + 액션 인사이트
10.  **제안 시작 기능** — 4종 컨텍스트(고객사/실적/시황/과거) + RAG 도메인 지식 → POSCO 정중 톤 3~4줄 행동 지침

#### 5.1.3 기술 스택

| 영역 | 기술 |
|---|---|
| **LLM Agent Framework** | **LangGraph** (StateGraph) — 5단계 Agent DAG 오케스트레이션, 조건부 분기 |
| **LLM SDK** | **LangChain** `ChatAnthropic` + **Anthropic Claude Sonnet 4**  |
| **RAG / VectorDB** | **PGVector** (PostgreSQL extension) + **OpenAI text-embedding-3-small** |
| **임베딩 대상** | 노션 PRD 청크(7) + customer_profile(9) + key_features(60) — 총 76개 벡터 |
| Backend | FastAPI, SQLAlchemy 2.x async, asyncpg, Pydantic v2 |
| DB / Cache | PostgreSQL 16 (+ pgvector), Redis 7 (Docker) |
| Frontend | Next.js 15 App Router, TanStack Query, ky, Tailwind, Framer Motion |
| 인증 | SSO/JWT 교체 가능 구조 |

### 6.2 정성적 효과

- **2차 인터뷰 피드백** (개발 완료 후 2명 검증):
  - *"가이드값 달성률 화면 한 장으로 월말 마감 스트레스가 사라질 것 같다"* (선재 담당)
  - *"유사 과거 시황 카드의 현재 대비 delta + 액션 인사이트는 베테랑이 머리로 하던 걸 자동화한 느낌 — 신입에게 가장 도움될 것"* (후판 담당)
  - *"메인 대시보드의 추천 질문 3개가 매일 다르게 나와서 응대 시나리오 준비에 큰 도움"* (후판 담당)
- **재현성 확보**: LLM `temperature=0` + `tool_use` schema 강제 + RAG retrieval 결정론적 ranking → 같은 입력에 같은 분석 → 베테랑·주니어 무관 균일 품질
- **노하우 자산화**: 영업담당자의 산업 인사이트가 *RAG 임베딩 (customer_profile sensitive_topics + risk_factors) + 프롬프트 도메인 방법론* 에 영속화
- **의사결정 근거 확보**: "왜 이 등급?" 에 대해 *달성속도·전년대비·시황영향* 3축 + RAG 검색된 도메인 베스트프랙티스로 항상 답변 가능

## 10. 기타 참고사항

### 10.1 우리가 강조하고 싶은 차별점

1. **사용자 인터뷰 기반 — "현장이 원하는 것"으로부터 시작**
   - 1차 인터뷰 5명 → 주제 변경 (알림 봇 → RAG 기반 통합 대시보드)
   - 2차 인터뷰 2명 → 활용성 검증 ("매우 높을 것")
   - *"우리는 만들고 싶은 걸 만든 게 아니라, 현장이 원하는 걸 만들었다"*

2. **표준 AI Agent 스택 채택 + 도메인 전문가 방법론 결합**
   - **LangGraph** StateGraph (Agent 오케스트레이션) + **LangChain** `ChatAnthropic` (LLM 추상화) + **PGVector** RAG (도메인 지식 검색)
   - BEFORE/AFTER 정량 실험으로 효과 검증 (formant 일치율 76→86%, briefing 길이 191→234자)

3. **데이터 모델 단계의 비즈니스 무결성**
   - 단일 행 단위 (판매그룹/제품/고객사) 스키마 → 결함 4 (분모 불일치) 구조적 해소
   - variant_code 자동 분기 → 다제품 거래처 통합 관리

4. **확장 가능한 풀스택 + Agent DAG 구조**
   - FastAPI 라우터 단위 분리 / 캐시 정책 24h scope 화 / LangGraph 노드 단위 재사용 / RAG 임베딩 파이프라인 모듈화
   - **POC 종료 후 운영 시스템으로 바로 이관 가능한 구조**

### 10.2 추후 비전 — "영업사원 개인화 RAG + 노하우 자산화"

> 인터뷰에서 가장 인상적이었던 한 마디:
> *"영업사원은 자신만의 노하우가 있어요. 엑셀에 다 있는데 시스템엔 못 녹입니다."*

이 한 마디가 다음 단계 비전입니다:

- 영업담당자가 **자신만의 지표 / 가중치 / 거래처별 메모** 를 시스템에 등록 → **개인화 RAG 노트북** 생성
- 본인 엑셀을 업로드 → AI 가 자연어로 노하우를 추출해 PGVector 에 임베딩 → 본인 customer 카드에 *"내 메모 RAG 검색 결과"* 자동 주입
- 결과: *베테랑 1명의 10년 노하우 → 조직 전체 자산화* (RAG 검색으로 모든 동료가 활용)
